Sécurité

Pas de vault partagé. Tout reste sur votre machine.

Aucun coffre cloud à nous. Pas de SaaS qui garde vos secrets. Vos clés API, credentials et configs vivent en local — vous déployez avec vos keys sur votre compte Outscale.

Le vrai risque, ce n’est pas « un vault quelque part » : c’est perdre votre machine ou ne pas la verrouiller. Sécurisez le poste (disk chiffrement, session lock) — le reste ne quitte pas votre bureau.

local-first · no shared vault · vos keys · credentials locaux · zero trust machine · chiffrement disque · session lock

Git privé

Simulations versionnées sur votre repo — jamais de secrets dessus.

Chaque simulation vit d’abord en local. Quand vous voulez un historique d’équipe, vous poussez vers un repo Git privé à vous — typiquement un *-infra dédié à la config. Une branche = une variante (main pour le live, sim/… pour les drafts).

Ce repo ne sert qu’à ça : project.yaml, layouts, Terraform généré, specs OKS — l’historique de la stack. Pas le monorepo applicatif, pas le pipeline de deploy app. On ne mélange pas code produit et gestion d’infra : le repo app clone/deploy d’un côté, le config-history versionne la simulation de l’autre.

Aucun secret ne part : pas de PEM, pas de .env, pas de tfvars, pas de kubeconfig, pas de state. Credentials restent dans le coffre local. Git = blueprint versionné, machine = keys.

private git · config-history · *-infra · branches · sim/ · main · no secrets in git · IaC history · separation of concerns
