Simple comme un PaaS.Flexible comme un IaaS.

01 / CONNECTERTout commence par ton projet.

01 / PaaS + BaaS → IaaS

Tu as déjà une app. Pas encore ton infra.

Une application sur un PaaS, les données sur un BaaS, les fichiers ailleurs. bige-ops permet de composer l’infrastructure qui les accueillera sur ton propre compte cloud.

Comprendre cette étape ↗

02 / Compte → dépôt → branche

Connecte GitHub. Choisis ce qui part.

Relie ton compte, sélectionne le dépôt et la branche. Identifie le front, l’API et les workers à déployer : ton code reste dans ton GitHub.

Comprendre cette étape ↗

03 / Visual → Terraform

Dessine ce que les plateformes te cachaient.

Place l’application, PostgreSQL et le stockage objet sur le Visual. bige-ops écrit alors un Terraform dans le projet : les ressources compute et database s’y lisent avant le déploiement.

Comprendre cette étape ↗

04 / HTTPS → app → base privée

Ouvre ton app. Protège le reste.

Le load balancer ouvre le HTTPS sur le port 443. L’application et PostgreSQL restent sur le réseau privé du compte. La région est celle ouverte sur ce compte : sur Outscale, cloudgouv-eu-west-1 est la Région SecNumCloud 3.2.

Comprendre cette étape ↗

05 / Scanner → comprendre → corriger

Avant de partir, regarde les risques.

Le scan relie les failles du code et des dépendances à leur contexte. CWE, CVE, route exposée, version corrigée : prépare une issue GitHub pour agir.

Comprendre cette étape ↗

06 / Copier → vérifier → basculer

Tes données deviennent souveraines.

Choisis un cloud souverain et une région adaptée. Migre ta base, copie tes objets, puis vérifie avant de basculer : tes données rejoignent une infrastructure sous ton contrôle.

Comprendre cette étape ↗

07 / Build sur VM / GitHub Actions → GHCR

Ton code devient une image prête à tourner.

Construis sur la VM, ou prépare une CI GitHub Actions qui construit et publie dans ton GHCR privé. Tu relis la pull request proposée avant de l’intégrer.

Comprendre cette étape ↗

08 / Test local → plan → déploiement

Du test local au vrai déploiement.

Le test local tourne sur le poste. Le plan liste les ressources qui vont être créées. Après confirmation, Outscale ou OVHcloud les facture sur le compte choisi, et le Terraform généré reste dans le dépôt du projet.

Comprendre cette étape ↗

09 / Pause · Start · Restart · Deploy

Et demain, tu gardes la main.

Mets en pause ou démarre les VM compatibles, redémarre un service, consulte ses logs. Choisis une branche à déployer et suis les opérations depuis la même app gratuite.

Questions sur le déploiement

Comment bige-ops déploie sur le compte cloud ?

Le Visual produit un Terraform dans le projet. Le plan est relu dans l’app. La confirmation crée les ressources sur le compte Outscale ou OVHcloud, en bêta. Le fournisseur les facture.

Qu’est-ce que bige-ops écrit dans le projet ?

Le Terraform généré depuis le Visual, plus les fichiers de configuration que l’app propose de relire. Le code applicatif reste dans le dépôt GitHub choisi.

Pourquoi Outscale est indiqué en bêta ?

Les VM, OKS et l’Object Storage Outscale sont branchés et utilisables, pas encore présentés comme un périmètre fermé. Le détail est sur la page Pourquoi Outscale et dans le périmètre de la bêta.
