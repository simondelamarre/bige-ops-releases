Zero → Hero

Le starter kit pour bien commencer sur Outscale.

Estimations catalogue, layouts prêts à l’emploi, simulations de stack — de zéro à une architecture déployable. Vous validez le design et le € avant d’engager le cloud.

Pas besoin de compte Outscale pour commencer. Mode projection : créez des simulations, composez le layout, lisez le € HT/mois (catalogue public) — même sans credentials. Connectez le compte plus tard pour inventory, plan et apply sur votre tenant — y compris SecNumCloud / cloud souverain.

Visual · Flow

Vue flow interactive — droit au but sur les setups.

Le canvas flow (Visual) est la vue interactive de la stack : VMs, OKS, volumes, OOS, liens réseau — vous voyez la topologie, vous cliquez le nœud, vous corrigez le setup dans l’inspector. Pas besoin de chercher le bon fichier : le flow vous mène au problème, puis à la config à jour.

Drop, liens, estimate sur les nœuds, Save + generate. Quand quelque chose cloche (placement, réplicas, backup, sizing), vous restez dans le flow pour le gérer — du symptôme au setup, sans quitter le schéma mental.

Visual · flow · canvas · inspector · topology · setup · droit au but

Mode expert

Édition des fichiers de config — quand le flow ne suffit pas.

Le canvas couvre le setup du quotidien. En mode expert, vous ouvrez les fichiers de la simulation (project.yaml, Terraform généré, specs OKS, scripts) dans le Workspace : arbre + éditeur, Save local, puis validate / generate / plan. C’est le chemin ops pour peaufiner, débloquer un cas limite, ou reprendre une materialization à la main.

Diffs & commits : versionner ces changements sur votre GitHub config-history (branches sim/…, main) avec une revue claire avant push — contrat produit et feuille de route des interfaces : mode expert · diffs & commits.

expert · fichiers · Workspace · diff · commit · config-history

Pricing

Estimations indicatives — pas un devis Outscale.

Avant même d’avoir un account, vous obtenez vos premières stacks et des estimations € HT/mois à partir du catalogue public embarqué. Utile pour projeter et comparer — pas pour promettre la réalité commerciale de votre facture.

Le prix réel dépend de votre tenant, de vos négos, options et conditions Outscale. bige-ops n’est pas connecté en temps réel au pricing cloud : le catalogue peut évoluer, décaler, ou différer de ce que vous facture Outscale.

À retenir : estimate = aide à la décision. Devis / bill = Outscale (et votre commercial).

estimate · catalogue public · indicative · not a quote · no live pricing feed · tenant · nego

Sécurité

Pas de SaaS secrets. Vos credentials, votre responsabilité.

bige-ops ne propose aucun vault partagé et aucun coffre cloud à nous. Rien n’est synchronisé vers un backend bige-ops — pas de partage SaaS de vos clés avec l’outil.

Les secrets d’infra “réels” (accès runtime, credentials cloud une fois la stack live) vivent côté Outscale après deploy — c’est le cloud qui les détient, pas nous. Pour travailler en local, vous pouvez enregistrer credentials / valeurs de coffre sur votre machine (fichiers locaux). Si vous avez déjà un vault d’entreprise, vous restez libre de l’utiliser en dehors de bige-ops : l’app n’impose pas le sien.

Vos secrets → votre responsabilité : sécurisez le poste (chiffrement disque, session lock), gérez qui a accès à la machine. On ne stocke pas vos clés “quelque part pour vous”.

no SaaS vault · local credentials · deploy · your secrets your responsibility

Git privé

Simulations versionnées sur votre repo — jamais de secrets dessus.

Créer un projet → nouveau repo GitHub privé (config-history). Créer une simulation → branche sim/…. Promote → alignement main (stack live). Deploy → toujours la vérité live / main. Rollback = snapshot puis plan/apply — emulate avant d’engager le cloud.

Ce repo ne sert qu’à ça : blueprint infra, pas le monorepo app. Aucun secret poussé. Détail du flow : GitHub config-history (emulate deploy & rollback).

Périmètre

On aide à démarrer. On ne fait pas tout.

Projection, presets, generate, apply — un kickoff / starter kit, pas une infra qui remplace l’intelligence humaine. Quand vous scalez, c’est à vous de gérer (run, capacité, incidents, choix prod). Pas un MSP, pas votre DBA, pas la négociation commerciale Outscale.

Les détails : périmètre, VMs, OKS & pods, bases de données, bases complexes, OOS & backups (formulaires réplicas / nœuds / buckets → maj setup directe), mode expert · diffs & commits.

Glossaire

Définitions (liens depuis la page).

Visual / Flow
Canvas interactif de la topologie (Vue Flow). Clic nœud → inspector → maj setup directe. Pour aller au problème et le corriger dans le flow, sans perdre le schéma mental.
Projection
Mode sans credentials Outscale : vous composez des simulations et lisez une estimation catalogue. Inventory / plan / apply restent bloqués jusqu’au login.
Simulation
Variante de stack versionnable (layout + coût projeté). Drafts en parallèle du live ; promote ou apply pour aligner la prod. Editable aussi en mode expert (fichiers) et versionnée via diffs / commits.
Estimate
Projection € HT/mois depuis le catalogue public embarqué. Indicatif — pas un devis Outscale, pas de feed pricing temps réel.
Mode expert
Édition directe des fichiers de config de la simulation (Workspace : arbre + éditeur). Complète le Visual / Flow quand il faut peaufiner YAML, Terraform ou specs. Voir expert-config.html.
Diffs & commits
Revue des changements locaux puis commit / push sur le config-history (sim/… ou main). Feuille de route UI : expert-config.html. Distinct du plan Terraform avant apply.
SecNumCloud
Qualification ANSSI pour le cloud de confiance. Outscale propose une région SecNumCloud ; bige-ops cible aussi ce terrain.
Cloud souverain
Cloud français / données et contrôle sous juridiction nationale. Outscale + SecNumCloud ; l’outil reste local-first, sans coffre SaaS à nous.
Deploy / Apply
Pousser la stack sur votre compte Outscale (plan puis apply). Credentials requis. Distinct du push Git config-history.
Config-history
Repo Git privé : projet→repo, simulation→branche sim/…, promote→main, deploy=main. Pas le repo app. Jamais de secrets. Voir github-config.html.
Promote
Draft → live. Côté Git : main. Snapshot pré-promote pour rollback config puis plan/apply.
OKS
Outscale Kubernetes Service — Kubernetes managé (control plane géré). Vous travaillez clusters / workloads ; Outscale opère le plan de contrôle.
IaaS
Infrastructure as a Service : VMs / VPS, volumes, réseau, IP… Vous composez la machine ; le cloud fournit le compute.
PaaS
Platform as a Service : couches managées (ex. OKS). Moins d’ops bas niveau, plus de focus apps / clusters.
Multi-tenant
Plusieurs comptes / projets Outscale sur le même poste : bascule dev, prod, client, SecNumCloud sans rejouer tout le setup.
Inventory
Liste live des ressources sur votre compte Outscale (VMs, volumes, réseau, OKS…). Base de la rétro et du resync.
Reverse engineering
Partir de l’inventory cloud, reconstruire une config exploitable, puis optimiser (sizing, €, Terraform / specs régénérés).
Terraform
Artefact généré depuis la simulation — pas l’interface principale. Materialization pour apply sur votre compte.
Materialization
Ce que generate écrit sur disque : Terraform, specs OKS, YAML apps. La vérité produit reste la simulation ; ces fichiers sont la couche d’apply.
