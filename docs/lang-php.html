bige-ops Gratuit

PHP sur Outscale

Laravel pour les produits SaaS, WordPress pour les sites et la publication, Symfony pour les applications d’entreprise : PHP reste partout. bige-ops le pose sur Outscale avec ses bases MySQL ou MariaDB en subnet privé, chiffre la stack et lit tes routes Laravel et WordPress.

En bref. Runtime php dans bige-ops : API sur le port 8080, front sur le 80, 512 MiB par défaut. Scan : routes Laravel et WordPress, Blade non échappé, dépendances Composer (Packagist) via OSV.

Frameworks et bibliothèques

Les deux frameworks PHP les plus déployés ont leur module de routes dans bige-ops ; Symfony se déploie de la même façon.

Laravel

Le framework PHP des équipes produit : Eloquent, files, Horizon, Sanctum. bige-ops lit Route::get(), Route::match() et les groupes Route::prefix() ; ->middleware('auth') marque une route protégée, et les sorties Blade non échappées {!! !!} sont relevées pour l’audit.

documentation officielle · Laravel sur OpenCVE

WordPress

Le CMS le plus utilisé du web, et son écosystème d’extensions (WooCommerce en tête). bige-ops reconnaît un site WordPress à son wp-config.php et lit les routes de l’API REST déclarées par register_rest_route().

documentation officielle · WordPress sur OpenCVE · WooCommerce sur OpenCVE

Symfony

Les composants et le framework derrière une large part du PHP d’entreprise. Il se conteneurise et se déploie sur Outscale comme Laravel (PHP-FPM ou serveur web intégré à l’image) ; ses dépendances Composer passent par OSV comme les autres.

documentation officielle · Symfony sur OpenCVE

Composer et PHP-FPM

Composer gère les paquets Packagist ; PHP-FPM sert l’application derrière nginx ou Apache dans l’image. bige-ops lit require et require-dev de chaque composer.json.

documentation officielle · PHP sur OpenCVE · Guzzle sur OpenCVE

Faire tourner PHP sur Outscale avec bige-ops

Le runtime php de bige-ops construit ton image depuis le Dockerfile du dépôt (PHP-FPM, Apache ou FrankenPHP : c’est ton choix d’image) et l’expose sur le port 8080, avec un front sur le port 80 si tu en déclares un. Les workers (queues Laravel, Horizon, Symfony Messenger) partagent la VM app.

TopologieSur OutscalePour
single-vmune VM {name}-all avec IP publique : apps et bases en Docker Composeprototype, démo, environnement de test
multi-vmVM app en subnet public derrière un LBU, une VM privée par base (security groups au CIDR du Net), NAT pour la sortiela production simple et lisible
okscluster OKS (control plane managé + nodepools), un Deployment par service, Service LoadBalancer → LBUle scale horizontal, les microservices, l’HPA
bige-ops add layout php-app --name shop
# ou sur mesure :
bige-ops add layout custom --runtime php --web same --worker \
  --db mysql --db redis --topology multi-vm --lbu

Le layout php-app part sur PostgreSQL + Redis ; le bâtisseur custom te laisse choisir MySQL ou MariaDB. Détail : layouts & topologies.

Ce que le scan bige-ops fait pour PHP

En mode direct, sans clé ni LLM, bige-ops parse tes sources PHP avec tree-sitter :

  • Routes : Laravel (Route::get, Route::match, préfixes) et WordPress (register_rest_route). ->middleware('auth') marque une route protégée ; une route sensible (/admin, /account, /payment…) sans signal d’authentification ressort « non sécurisée » (CWE-639).
  • Code : secrets en dur (CWE-798), eval() et exec() (CWE-78), et les sorties Blade {!! !!} pour l’audit approfondi.
  • Dépendances : paquets Packagist de composer.json rapprochés d’OSV ; un front JavaScript (package.json) passe aussi par OSV et par l’analyse XSS.

Avec ta clé OpenCVE, MySQL, MariaDB, Redis et une image nginx sont rapprochés automatiquement de leur fiche. Pour le runtime PHP lui-même, garde la fiche PHP sur OpenCVE en référence.

Bases de données typiques

PHP s’accorde naturellement avec la famille MySQL, et Laravel parle aussi très bien PostgreSQL.

Règle d’or, quelle que soit la base : jamais exposée à Internet. En multi-VM elle vit dans le subnet privé, sans IP publique, derrière un security group limité au CIDR du Net ; sur OKS elle reste un Service interne (ClusterIP). Détail : réseau · ouvrir ou non et bases de données.

Versions à épingler

PHP publie ses dates de support : 8.4 (sécurité jusqu’au 31 décembre 2028) et 8.5 (jusqu’au 31 décembre 2029) sont les bons choix ; 8.3 reste couvert jusqu’à fin 2027 et 8.2 jusqu’au 31 décembre 2026. WordPress demande PHP 8.3 ou plus. Laravel corrige les bugs 18 mois et la sécurité 2 ans par version majeure. Sources : versions supportées de PHP · politique de support Laravel · CVE : PHP sur OpenCVE.

OpenCVE, le référentiel CVE de bige-ops

Pour savoir quelles vulnérabilités touchent les briques de ta stack, bige-ops s’appuie sur OpenCVE. OpenCVE agrège les CVE publiées (NVD, MITRE, catalogue KEV de la CISA…), les enrichit avec les scores CVSS et EPSS et les range par fournisseur et par produit, consultables dans son explorateur. Le projet est open source : son code, ses issues et les contributions de sa communauté vivent sur GitHub, et il s’installe aussi chez toi. Merci à ses mainteneurs et à tous ceux qui font vivre ce référentiel : c’est grâce à eux que chaque composant de ta simulation a sa fiche CVE à jour.
