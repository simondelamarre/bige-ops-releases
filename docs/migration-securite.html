Les détails techniques et les limites

Migre sans peur

Quitter un PaaS, c’est d’abord déplacer des données. bige-ops le fait en copie contrôlée : la source n’est jamais supprimée, rien n’est écrasé.

  • Object Storage. Connecte AWS S3, Cloudflare R2, Outscale OOS ou un endpoint compatible S3. Explore, prévisualise tes fichiers, puis reproduis un bucket ou tous sur OOS : mêmes noms, copie parallèle, reprise après une coupure. Voir
  • Bases de données. Chaque base a son panneau Données : dump, envoi vers l’Object Storage, restauration, migration depuis une autre base. Voir

Comment bige-ops trouve tes failles

  1. Il lit sur ton poste la branche sélectionnée de chaque dépôt et oublie les résultats devenus obsolètes quand tu changes de branche.
  2. Il groupe les pages et API par dépôt, stack et service, puis les relie à leur exposition réelle : publique, interne ou source uniquement.
  3. Il cherche les erreurs classiques : mots de passe écrits en clair, requêtes à la base construites avec ce que tape l’utilisateur, API ouverte à n’importe quel site.
  4. Il compare les versions réellement installées aux bases publiques (OSV) et, avec ta clé OpenCVE, enrichit les CVE avec leur statut et leurs correctifs connus.
  5. Il écarte le bruit historique non applicable et classe les actions : exposition Internet, sévérité, exploitabilité puis version corrigée.

Pourquoi le refaire toi-même ? C’est chez toi, et c’est gratuit.

Gratuit, sans intermédiaire

bige-ops est gratuit. Ton cloud, tu le paies à ton fournisseur, sur ton compte. Personne ne se place entre les deux.

Avant de déployer, la simulation t’en donne une estimation dans l’app, sur les tarifs publics du fournisseur : le catalogue se synchronise par la CLI, et la remise que tu négocies vient en plus. Comment l’estimation est faite

Démarrer en trois étapes

  1. Installe : la commande ci-dessus sur macOS, l’AppImage ou le .deb sur Linux.
  2. Simule et teste : connecte-toi avec GitHub, choisis un dossier, pars d’une stack prête et lance-la en local.
  3. Déploie : tu connectes ton compte cloud quand tu es prêt, tu relis le plan, tu déploies.
