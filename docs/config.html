01 Lire02 Préparer03 Appliquer04 Revoir
01 · LIRE

Ouvrir les fichiers du projet.

L’arborescence rassemble le document du projet et les fichiers de travail. Lire les services, leurs ressources et les options de déploiement sans quitter l’app. La vue visuelle et les fichiers racontent la même infrastructure, à deux niveaux de détail.

Stack visuelle→Configuration lisible

Le document du projet et les fichiers générés n’ont pas le même rôle.

02 · PRÉPARER

Modifier le brouillon.

Changer le document de configuration puis relire les différences avant de l’appliquer. Une modification peut être conservée ou abandonnée. L’édition du fichier n’exécute pas, à elle seule, un changement sur les ressources cloud.

Configuration actuelle→Brouillon à relire

Les changements non appliqués restent distincts de la configuration retenue.

03 · APPLIQUER

Mettre à jour les fichiers générés.

bige-ops valide la configuration et vérifie que le document de départ n’a pas changé entre-temps. Si une autre modification est intervenue, elle doit être résolue avant de poursuivre. La version appliquée réaligne ensuite le document et les représentations de la stack.

Brouillon vérifié→Configuration synchronisée

Le contrôle de version évite d’écraser silencieusement une modification concurrente.

04 · REVOIR

Examiner le plan cloud.

Ouvrir la revue avec la configuration choisie. Relire les ressources concernées et les opérations proposées, puis décider de les lancer. Le suivi Git garde la trace des fichiers autorisés et de leur synchronisation avec le dépôt de configuration.

Configuration appliquée→Revue de l’action cloud

Appliquer la configuration et déployer ses ressources restent deux actions distinctes.

Questions fréquentes

Apply config déploie-t-il la stack ?

Non. Cette action valide et synchronise la configuration. La revue et le lancement des opérations cloud sont distincts.

Faut-il une IA pour modifier la configuration ?

Non. Les fichiers et les outils visuels se manipulent directement. L’assistance IA est un choix ; son périmètre est décrit dans sa propre page.

Que se passe-t-il si le fichier a changé pendant l’édition ?

L’application vérifie la version du document de départ. Une divergence doit être résolue avant l’application afin de ne pas écraser silencieusement le travail concurrent.
