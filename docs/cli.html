CLI · app · OKS

Le kickoff se fait dans l’app desktop (Visual, Workspace, Chat). La CLI bige-ops existe : c’est le même moteur (l’app l’appelle). Pour OKS, oui on s’appuie sur des CLI kube — oks-cli et kubectl — sous le capot.

On utilise la CLI pour OKS ? Oui, mais pas comme produit « terminal-first ». L’app (ou bige-ops apply --target oks / bige-ops deploy) lance oks-cli pour le cluster et kubectl apply pour les manifests. Vous pouvez aussi enchaîner à la main une fois le kubeconfig généré.

Qui fait quoi

OutilRôleQuand
App desktop Composer, estimate, review, deploy Chemin nominal (kickoff)
bige-ops validate / generate / plan / apply / deploy Sous l’app, ou script / CI / terminal
oks-cli Projet / cluster / nodepools / kubeconfig OKS Via apply --target oks (embarqué)
kubectl Appliquer / inspecter les manifests oks/apps/ Via deploy topologie oks, ou à la main

OKS en pratique

1. Simulation topologie oks (Visual ou bige-ops add stack --topology oks). 2. generate → specs sous bige-ops/oks/ + apps YAML. 3. apply --target oks → oks-cli. 4. deploy → kubectl apply des Deployments (réplicas = pods).

Détail produit OKS : OKS & pods. Doc CLI complète : dans l’app (Docs) — pages cli/oks, cli/overview.

Ce que ce n’est pas

Pas un substitut à votre formation kubectl. Pas un IDE kube. La landing « CLI Kubernetes » = même moteur + outils kube disponibles, pas « tout se fait uniquement en CLI ».
