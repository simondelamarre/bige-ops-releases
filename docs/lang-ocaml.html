bige-ops Gratuit

OCaml sur Outscale

OCaml allie typage fort, compilation native et excellentes performances : un choix solide pour des backends web sûrs et sobres. bige-ops déploie ton service OCaml sur Outscale comme un service custom construit depuis ton Dockerfile, avec ses bases en subnet privé.

En bref. Service custom dans bige-ops : image construite depuis ton Dockerfile (opam + dune), port et mémoire au choix. Topologies mono-VM, multi-VM ou OKS.

Frameworks et bibliothèques

Les frameworks web OCaml les plus utilisés.

Dream

Un framework web tout-en-un dans un seul module : routeur, sessions, formulaires protégés contre le CSRF, WebSockets, GraphQL, HTTPS et HTTP/2, et accès SQL via Caqti.

documentation officielle

Opium

Un framework léger inspiré de Sinatra, pour des API REST simples.

documentation officielle

Ocsigen et Eliom

Eliom écrit client et serveur dans le même programme OCaml, servi par Ocsigen Server ; le client est compilé en JavaScript.

documentation officielle

Caqti

L’interface commune aux bases relationnelles : pilotes PostgreSQL (postgresql://), MariaDB (mariadb://) et SQLite, choisis par l’URI de connexion.

documentation officielle · PostgreSQL sur OpenCVE · MariaDB sur OpenCVE

opam et dune

opam installe le compilateur et les paquets, dune construit le projet ; un Dockerfile multi-étapes part de l’image ocaml/opam et livre un binaire natif dans une image minimale.

documentation officielle · opam sur OpenCVE · OCaml sur OpenCVE

Faire tourner OCaml sur Outscale avec bige-ops

Déclare ton service en kind: custom avec l’image construite depuis ton Dockerfile (ou un dépôt Git), son port et sa mémoire : un binaire natif OCaml se contente de peu. En multi-VM il partage la VM app ; sur OKS il devient un Deployment (une image est requise pour un pod).

TopologieSur OutscalePour
single-vmune VM {name}-all avec IP publique : apps et bases en Docker Composeprototype, démo, environnement de test
multi-vmVM app en subnet public derrière un LBU, une VM privée par base (security groups au CIDR du Net), NAT pour la sortiela production simple et lisible
okscluster OKS (control plane managé + nodepools), un Deployment par service, Service LoadBalancer → LBUle scale horizontal, les microservices, l’HPA
# service_config (extrait)
web:
  kind: custom
  image: registry.example.com/acme/ocaml-web:1.0.0
  port: 8080
  memory_mb: 256

Les bases du catalogue bige-ops (PostgreSQL, MariaDB, Redis…) se déclarent à côté, en VM privée ou en pod.

Bases de données typiques

Caqti couvre PostgreSQL et MariaDB, les deux bases les plus courantes avec OCaml.

BaseAvec ce langageCVE
PostgreSQLCaqti (postgresql://), Petrol. Stack : Phoenix + PostgreSQL.fiche OpenCVE
MariaDBCaqti (mariadb://). Stack : WordPress + MariaDB.fiche OpenCVE

Règle d’or, quelle que soit la base : jamais exposée à Internet. En multi-VM elle vit dans le subnet privé, sans IP publique, derrière un security group limité au CIDR du Net ; sur OKS elle reste un Service interne (ClusterIP). Détail : réseau · ouvrir ou non et bases de données.

Versions à épingler

Épingle le compilateur dans ton switch opam et tes paquets dans un fichier de lock opam. Sources : versions d’OCaml · sécurité OCaml · CVE : OCaml sur OpenCVE · opam sur OpenCVE.

OpenCVE, le référentiel CVE de bige-ops

Pour savoir quelles vulnérabilités touchent les briques de ta stack, bige-ops s’appuie sur OpenCVE. OpenCVE agrège les CVE publiées (NVD, MITRE, catalogue KEV de la CISA…), les enrichit avec les scores CVSS et EPSS et les range par fournisseur et par produit, consultables dans son explorateur. Le projet est open source : son code, ses issues et les contributions de sa communauté vivent sur GitHub, et il s’installe aussi chez toi. Merci à ses mainteneurs et à tous ceux qui font vivre ce référentiel : c’est grâce à eux que chaque composant de ta simulation a sa fiche CVE à jour.
