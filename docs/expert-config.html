bige-ops Beta démo

Mode expert · fichiers, diffs & commits

Visual / Flow pour composer. Quand il faut aller dans le détail : édition directe des fichiers de la simulation (project.yaml, Terraform généré, specs OKS, scripts…). Puis diffs et commits sur le config-history — la feuille de route des interfaces.

Deux vitesses. Flow = setup rapide. Expert = vérité fichiers + Git. Ni l’un ni l’autre ne remplace Outscale ; les secrets restent hors repo.

Mode expert aujourd’hui

Dans l’app, l’onglet Workspace expose l’arbre des fichiers du projet et un éditeur (YAML, HCL, scripts). Vous ouvrez bige-ops/project.yaml, un module Terraform, un manifest OKS — vous corrigez, vous Save en local, puis validate / generate / plan.

C’est le chemin expert : hors formulaires Visual, quand un champ manque, un layout custom, ou une materialization à peaufiner. La simulation reste la vérité produit ; les fichiers sont ce que vous versionnez et appliquez.

Diffs & commits — où on va (interfaces)

Aujourd’hui : push GitHub (souvent un commit groupé), revue plan Terraform avant apply, diff config vs snapshot dans la revue Apply. Ce n’est pas encore un « Git desktop » complet dans bige-ops.

Cible produit (à câbler dans les UI) :

  • Diff fichiers — voir clairement ce qui a changé (Visual Save, édition expert, generate) avant de committer.
  • Commit intentionnel — message, branche (sim/… vs main), pas un push opaque.
  • Lien Flow ↔ fichiers — du nœud Visual au fichier touché, et inversement.
  • Garde-fous — jamais de secrets dans le diff poussé ; rappel OOS / backup / perte de données sur les destroys.

Convention Git déjà documentée : GitHub config-history (projet→repo, sim→branche, promote→main ; deploy via l’app + sync GitHub ; autres Git WIP ; rollback Git manuel sur GitHub). Cette page fixe le contrat expert + diff + commit pour guider les prochaines itérations d’interface.
