01 · PARTIR DE L’EXISTANT

Ouvrir la stack active.

Ouvrir le cloud concerné et retrouver sa configuration active. Cette base sert à comparer les prochains scénarios : même application, autres tailles de VM, autre répartition des services. Les ressources réellement présentes se consultent dans l’Inventaire.

Configuration de départ→Base de comparaison

La configuration active locale et l’état réel du cloud restent distincts.

02 · SIMULER

Créer une variante.

Dupliquer la configuration, nommer chaque hypothèse et la travailler dans Simulations. Une base séparée pour isoler sa charge ; une VM plus compacte pour revoir le budget. Le Hub conserve les variantes et leurs coûts estimés, sans provisionner ces ressources.

Une architecture→Plusieurs variantes chiffrées

Les estimations comparent les scénarios ; elles ne mesurent pas leurs performances.

03 · PARTAGER

Partager la variante dans GitHub.

Relier le dépôt de configuration puis partager les simulations. bige-ops choisit leur branche sim/<id> et pousse les fichiers autorisés. L’équipe peut retrouver les scénarios depuis le dépôt, lire leurs différences et continuer à travailler sur la même hypothèse.

Variante locale→Historique partagé

Branches sim/* pour les simulations ; main pour la configuration active.

04 · PROMOUVOIR

Choisir la configuration à promouvoir.

Choisir la simulation à promouvoir. bige-ops prépare la configuration active, conserve un état précédent et ouvre la revue des changements. Relire ce qui sera créé, modifié ou retiré avant de lancer l’action cloud. Le choix devient explicite et partageable.

Simulation retenue→Revue avant déploiement

Promouvoir prépare la revue ; le déploiement nécessite sa confirmation.

Questions fréquentes

Créer une simulation démarre-t-il des VM ?

Non. Une simulation décrit et estime des ressources. Leur création passe par une revue puis une action cloud explicite.

Peut-on travailler à plusieurs ?

Oui, en reliant un dépôt de configuration partagé et les accès GitHub nécessaires. Les simulations suivent la convention sim/<id> ; les variantes distantes peuvent être retrouvées localement. Il s’agit d’un échange versionné, pas d’une édition simultanée en temps réel.

La promotion permet-elle de restaurer les données ?

Non. La promotion conserve un état de configuration pour relire un retour en arrière. Sauvegarder ou restaurer les données relève du parcours dédié à la migration et aux sauvegardes.
