Une licence fait partie du choix d’infrastructure

Un logiciel peut rester téléchargeable et son code consultable, tout en changeant les conditions d’usage. Dans le cloud, la différence est concrète : une licence peut autoriser une équipe à installer un composant pour son produit, mais encadrer différemment l’entreprise qui veut en proposer la fonction comme service à ses propres clients.

Trois évolutions montrent pourquoi il faut regarder la licence attachée à la version exacte, plutôt que se fier au nom du projet ou à une ancienne fiche technique.

MongoDB : la SSPL depuis 2018

MongoDB indique que les versions de Community Server publiées depuis le 16 octobre 2018 sont sous Server Side Public License (SSPL). Sa section 13 prévoit des obligations particulières lorsqu’une organisation met la fonction du logiciel à disposition comme service. Cela a pesé dans les décisions de fournisseurs qui ne souhaitaient pas proposer MongoDB Community comme base managée sous ces conditions.

Ce changement ne signifie pas qu’une application ne peut pas utiliser MongoDB, ni qu’un développeur ne peut pas l’installer sur une VM. Il faut distinguer l’usage interne du service offert par un fournisseur.

HashiCorp et Redis : d’autres trajectoires

En août 2023, HashiCorp a annoncé le passage de versions futures de plusieurs produits de MPL 2.0 à Business Source License 1.1 (BSL). Les versions précédentes n’ont pas été requalifiées par cette annonce : leur licence reste celle publiée avec chacune d’elles.

Redis a annoncé en 2024 une double licence RSALv2/SSPLv1 pour Redis 7.4 et les versions suivantes. Redis 8, publié en 2025, ajoute AGPLv3 comme option de licence, aux côtés des deux autres choix. Une même famille de versions peut donc demander une lecture plus fine qu’un simple badge « open source ».

Les quatre vérifications utiles

Avant d’adopter un composant, relever la version précise, lire le fichier LICENSE et les éventuels avis de changement, vérifier si l’usage envisagé est une offre hébergée à des tiers, puis confirmer que le fournisseur propose cette version avec un support adapté. Pour un service critique ou une offre commerciale, faire confirmer l’interprétation par les personnes compétentes dans l’organisation.

Le code ouvert à la consultation, une licence approuvée par l’Open Source Initiative et une licence utilisable sans restriction de service ne sont pas des synonymes.

La SSPL n’est pas approuvée par l’Open Source Initiative (OSI). MongoDB la présente comme une licence source-available ; il ne faut donc pas la qualifier de licence open source au sens de la définition de l’OSI.
