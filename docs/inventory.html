Les ressources de ton compte

Les détails techniques et les limites

Ton compte Outscale existe déjà ? bige-ops le lit, le comprend et l’affiche, avec une estimation de coût. Une partie est importable en composants, le reste est observé, et chaque ressource dit dans quel cas elle se trouve.

Lire le compte

  • bige-ops inventory fetch — interroge le compte et stocke un snapshot local : nets, subnets, VMs, volumes, snapshots, buckets OOS, security groups, keypairs, IP publiques, route tables, NAT, internet service, LBU, net peering, VPN, OKS.
    Les gateways VPN (client et virtual gateways) et les Subregions sont aussi récupérées : elles restent dans le snapshot brut, sans ligne dédiée dans la liste affichée.
  • bige-ops inventory show — affiche le résumé et l’estimation de coût.
  • bige-ops import selection --id i-xxxx — écrit du YAML depuis l’inventaire, puis lance generate.
  • bige-ops import plan — imprime les commandes terraform import suggérées. Rien n’est exécuté. 
bige-ops inventory fetch
bige-ops inventory show
bige-ops import selection --id i-0123456789abcdef
bige-ops import plan

La matrice

Chaque ressource renvoyée par l’API Outscale entre dans un état précis :

État Ressources Ce que tu peux en faire
Importé en composant VMs, volumes, nets, subnets, security groups (IDs adoptés), keypairs YAML généré, Terraform, édition dans l’app
Observé seulement route tables, NAT, internet service, IP publiques, Net peering, VPN, buckets OOS (listés, non réécrits en YAML), LBU importés (sans listeners ni backends), OKS (projets listés, non réécrits en YAML) affiché et compté, mais aucun Terraform de création
Local seulement nic, dhcp_options visibles en Visual / YAML, pas de Terraform généré
Catalogue de prix DirectLink tarifé au catalogue de prix

Le détail ressource par ressource, avec le pourquoi de chaque état, est sur Réseau avancé et LBU.

La philosophie. On lit, comprend et affiche. Un compte construit à la main reste le tien : l’inventaire te donne une carte et une estimation, sans rien réécrire derrière toi.

Status, destroy, forget

L’UI Inventaire montre des badges d’état (running / terminated / …) et une estimation. Pour supprimer une ressource cloud avec vérification : 

bige-ops inventory destroy --id vpc-xxx --cascade --plan
bige-ops inventory destroy --id i-xxx --cascade --yes
bige-ops inventory forget --terminated

Sans --yes : plan seulement. Avec --yes : delete + re-fetch ; le succès exige que la ressource ait disparu (ou soit un tombeau oublié). forget = snapshot local seulement (zombies API).

Danger — inventory clean --yes est destructif. Cette commande importe tout ce qui est importable, vide le projet, puis lance un terraform destroy sur le compte. Elle est à réserver aux comptes de test. Elle refuse de détruire les buckets OOS ; relis tout de même deux fois avant de la lancer.

Bon à savoir

  • L’import adopte les ressources que tu sélectionnes ; il ne fait pas entrer tout le compte dans un state Terraform.
  • Le tableau ci-dessus décrit exactement ce que l’import réécrit.
  • Les security groups affichés sont un point de départ de lecture ; l’audit de sécurité et de conformité se mène à côté.
  • L’exploitation du compte reste la tienne — périmètre.

Câblage réseau : réseau. Machines : VMs. Objet et backups : OOS. Où vit l’inventaire : projets & simulations.
