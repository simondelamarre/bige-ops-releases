Les commandes utiles.

Installer sur macOS

Puis ouvrir bige-ops depuis Applications.

brew install --cask simondelamarre/bige-ops/bige-ops

Mettre à jour une installation Homebrew

La détection d’une nouvelle version dans l’app ne remplace pas l’installation.

brew update
brew upgrade --cask bige-ops

Installer le paquet Debian téléchargé

Depuis le dossier qui contient le paquet de la release 0.11.1.

sudo apt install ./bige-ops-0.11.1-linux-x86_64.deb

Lancer l’AppImage téléchargée

Depuis le dossier qui contient l’AppImage de la release 0.11.1.

chmod +x bige-ops-0.11.1-linux-x86_64.AppImage
./bige-ops-0.11.1-linux-x86_64.AppImage

Les points à connaître.

Faut-il un compte cloud pour essayer ?

Non. Commencer par une simulation locale et son estimation. Le déploiement demande ensuite les accès au compte cloud choisi.

L’app est-elle disponible sur Windows ?

Les binaires publiés couvrent macOS Apple Silicon et Linux x86_64. Aucune version Windows n’est annoncée ici.

L’installation a-t-elle été vérifiée ?

Les artefacts 0.11.1 sont publiés sur GitHub et les formats ci-dessus correspondent à cette release. Le guide détaille les dépendances et le premier lancement ; une configuration locale particulière peut demander un diagnostic.

Ressources, réglages et détails techniques

Formats, dépendances et mises à jour : les détails pratiques de l’installation.

macOS : Homebrew

Une commande installe l’app et la prépare pour le premier lancement :

brew tap simondelamarre/bige-ops
brew install --cask bige-ops

Puis lance bige-ops depuis le Launchpad ou /Applications.

Linux : AppImage ou .deb

Télécharge l’AppImage ou le paquet .deb depuis la dernière release : 

chmod +x bige-ops-*-linux-x86_64.AppImage && ./bige-ops-*-linux-x86_64.AppImage
# ou
sudo apt install ./bige-ops-*-linux-x86_64.deb

macOS : premier lancement

Le cask Homebrew retire la quarantaine et signe l’app localement : elle s’ouvre directement. Si tu as installé l’app à la main, lance une fois dans Terminal : 

xattr -cr /Applications/bige-ops.app && codesign --force --deep --sign - /Applications/bige-ops.app
open /Applications/bige-ops.app

Mises à jour : vérifiées, pas automatiques

L’application vérifie s’il existe une version plus récente en lisant latest.json sur le dépôt de releases. Elle te le signale — et c’est tout. Il n’y a pas d’auto-install, pas d’updater silencieux, rien qui remplace le binaire dans ton dos.

Homebrew caskbrew upgrade --cask bige-ops
LinuxTélécharger la nouvelle AppImage ou le nouveau .deb

CLI embarquée

Le binaire bige-ops (build PyInstaller) est packagé dans l’application : c’est lui que l’app appelle pour validate, generate, estimate, plan, apply, deploy. Tu n’installes rien de plus pour démarrer. La CLI oks-cli d’Outscale est embarquée de la même façon.

La version de la CLI doit rester alignée avec celle de l’app. L’écran Settings affiche l’état : CLI introuvable, CLI désalignée, ou à jour. Si c’est désaligné, mets l’app à jour plutôt que de bricoler le PATH. Détail des commandes : CLI · app · OKS.

Dépendances système

L’app embarque un écran de diagnostic « Dépendances » qui teste ce qui est présent sur ton poste. Tu peux utiliser bige-ops en mode projection (design + estimation) sans rien de tout ça ; les outils deviennent nécessaires dès que tu testes en local, matérialises ou déploies.

OutilRequis pour
CLI bige-ops embarquéeTout le moteur : validate, generate, estimate
Terraformplan et apply sur l’infra Outscale
oks-cli embarquéCluster OKS : création, nodepools, kubeconfig
kubectlDeploy des manifests sur OKS, et sur le cluster local
Docker / SSHTests en local (Docker Compose) et deploy applicatif sur VMs (build + compose)
kindTests en local sur un cluster Kubernetes, sans compte cloud

Premier lancement

  • Choisis un workspace : un simple dossier local où vivront tes simulations.
  • Créer l’espace du cloud choisi dans l’app : Outscale ou OVHcloud en bêta. Renseigner les accès pour agir sur le compte, ou rester sans credentials en mode projection pour composer et estimer.
  • Crée une première simulation, teste-la en local si tu veux, puis validate / generate avant tout plan.

Où atterrissent les clés et les secrets : Secrets, coffre & credentials. Ce que l’outil couvre — et ne couvre pas : Périmètre. Concept de simulation : Simulations.

Bon à savoir

Ce que l’installation couvre. Pas de Windows. Pas de mise à jour automatique : c’est toi qui remplaces le binaire. Hors CLI bige-ops et oks-cli, pas de packaging des dépendances tierces : Terraform, kubectl, kind et Docker restent à ta charge, avec les versions de ton poste.
