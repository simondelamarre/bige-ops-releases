Installer & mettre à jour

bige-ops est une application desktop locale, gratuite, distribuée via GitHub Releases. Version courante : 0.3.0 (tag v0.3.0). macOS et Linux ; pas de Windows aujourd’hui.

Beta démo, gratuite. Le produit est jeune : il manque des choses et il reste des bugs. Dites-le — issues publiques : bige-ops-releases · issues.

Où récupérer l’app

Tout passe par le dépôt public simondelamarre/bige-ops-releases : le DMG macOS et le fichier latest.json utilisé pour la vérification de version.

  • macOS — DMG : dernière release, puis glissez l’app dans /Applications.
  • macOS — Homebrew : le tap simondelamarre/bige-ops expose un cask.
  • Linux : build disponible depuis les releases.
  • Windows : non supporté à ce jour. Pas de contournement propre, pas d’ETA à vous vendre.
brew tap simondelamarre/bige-ops
brew install --cask bige-ops
Cask vs release. Le cask Homebrew peut être en retard sur le tag GitHub (ex. cask 0.2.2 alors que la release est 0.3.0). Vérifiez brew info --cask bige-ops : si les numéros divergent, préférez le DMG latest.

Mises à jour : vérifiées, pas automatiques

L’application vérifie s’il existe une version plus récente en lisant latest.json sur le dépôt de releases. Elle vous le signale — et c’est tout. Il n’y a pas d’auto-install, pas d’updater silencieux, rien qui remplace le binaire dans votre dos.

InstallationMettre à jour
DMG macOSTélécharger la nouvelle release, remplacer l’app dans /Applications
Homebrew caskbrew upgrade --cask bige-ops
LinuxTélécharger et remplacer le binaire

CLI embarquée

Le binaire bige-ops (build PyInstaller) est packagé dans l’application : c’est lui que l’app appelle pour validate, generate, estimate, plan, apply, deploy. Vous n’installez rien de plus pour démarrer.

La version de la CLI doit rester alignée avec celle de l’app. L’écran Settings affiche l’état : CLI introuvable, CLI désalignée, ou à jour. Si c’est désaligné, mettez l’app à jour plutôt que de bricoler le PATH. Détail des commandes : CLI · app · OKS.

Dépendances système

L’app embarque un écran de diagnostic « Dépendances » qui teste ce qui est présent sur votre poste. Vous pouvez utiliser bige-ops en mode projection (design + estimation) sans rien de tout ça ; les outils deviennent nécessaires dès que vous matérialisez ou déployez.

OutilRequis pour
CLI bige-ops embarquéeTout le moteur : validate, generate, estimate
Terraformplan et apply sur l’infra Outscale
oks-cliCluster OKS : création, nodepools, kubeconfig
kubectlDeploy des manifests sur OKS
Docker / SSHDeploy applicatif sur VMs (build + compose)

Premier lancement

  • Choisissez un workspace : un simple dossier local où vivront vos simulations.
  • Créez un compte Outscale dans l’app et renseignez vos clés API — ou restez sans credentials en mode projection pour designer et estimer.
  • Créez une première simulation, puis validate / generate avant tout plan.

Où atterrissent les clés et les secrets : Secrets, coffre & credentials. Ce que l’outil couvre — et ne couvre pas : Périmètre. Concept de simulation : Simulations.

Limites honnêtes

Ce que l’installation ne vous donne pas. Pas de Windows. Pas de mise à jour automatique : c’est vous qui remplacez le binaire. Pas de packaging des dépendances tierces — Terraform, oks-cli, kubectl et Docker restent à votre charge, avec les versions de votre poste. Et l’app ne remplace ni votre SRE ni votre DBA : c’est un kickoff.
