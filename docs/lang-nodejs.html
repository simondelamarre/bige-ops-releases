bige-ops Gratuit

Node.js sur Outscale

Express, Fastify, NestJS, Next.js : l’écosystème Node.js fait tourner une bonne part des API et des fronts modernes. Sur Outscale, bige-ops le pose en mono-VM, en multi-VM derrière un LBU ou sur OKS, chiffre la stack au catalogue public et lit tes dépôts pour trouver routes ouvertes et dépendances vulnérables.

En bref. Runtime nodejs dans bige-ops : API sur le port 3001, front sur le 3000, 512 MiB par service par défaut. Scan le plus complet de bige-ops : routes de huit frameworks back, failles front (React, Vue, Svelte) et dépendances npm rapprochées d’OSV.

Frameworks et bibliothèques

bige-ops reconnaît ces frameworks dans ton package.json et dans le code : chacun a son module de détection de routes.

Express

Le socle minimaliste de l’écosystème : middlewares, app.get(), router.route(). bige-ops lit les routes déclarées sur app et router, y compris typées en TypeScript ; les réponses qui renvoient la requête telle quelle sont préparées pour l’audit approfondi.

documentation officielle · Express sur OpenCVE

Fastify

Le framework orienté performance et schémas JSON. Routes courtes (fastify.get), .route({ url, method }) et préfixes de plugins (register(plugin, { prefix })) sont détectés ; preHandler et onRequest comptent comme signaux d’authentification.

documentation officielle · Fastify sur OpenCVE

Hono

Léger, standard Web, multi-runtime. app.get(), app.on(['GET','POST'], path) et basePath() sont lus.

documentation officielle · Hono sur OpenCVE

Koa

Le successeur minimaliste d’Express, tout en middlewares async ; ses routeurs (router.get()) sont détectés.

documentation officielle · Koa sur OpenCVE

LoopBack

Framework d’API orienté OpenAPI. Les décorateurs LoopBack 4 (@get, @post, @operation) deviennent des routes.

documentation officielle · LoopBack sur OpenCVE

NestJS

L’architecture modulaire et typée des équipes produit. @Controller() donne le préfixe, @Get() / @Post() les routes ; @UseGuards() marque une route protégée, @Public une route ouverte, et un contrôleur sans guard visible ressort pour l’audit.

documentation officielle · NestJS sur OpenCVE

Next.js

Le framework React full-stack. Les route handlers (app/**/route.ts) et les routes pages/api sont lus depuis l’arborescence ; une route API Next.js est marquée « à vérifier » côté session.

documentation officielle · Next.js sur OpenCVE

tRPC

Des API typées de bout en bout sans schéma séparé. Les routeurs tRPC sont lus ; protectedProcedure et publicProcedure disent qui est protégé.

documentation officielle · tRPC sur OpenCVE

React, Vue, Svelte

Côté front, bige-ops cherche les injections HTML : dangerouslySetInnerHTML (React, Next.js), v-html (Vue), {@html} (Svelte) et les affectations innerHTML. Docs : Vue, Svelte.

documentation officielle · React sur OpenCVE · Vue sur OpenCVE · Svelte sur OpenCVE

Faire tourner Node.js sur Outscale avec bige-ops

Dans bige-ops, le runtime nodejs donne une API sur le port 3001 et un front sur le 3000 (512 MiB chacun), construits depuis le Dockerfile de ton dépôt. Le front peut être une SPA servie par Node (--web spa), le même runtime que l’API (--web same, typique de Next.js) ou absent.

TopologieSur OutscalePour
single-vmune VM {name}-all avec IP publique : apps et bases en Docker Composeprototype, démo, environnement de test
multi-vmVM app en subnet public derrière un LBU, une VM privée par base (security groups au CIDR du Net), NAT pour la sortiela production simple et lisible
okscluster OKS (control plane managé + nodepools), un Deployment par service, Service LoadBalancer → LBUle scale horizontal, les microservices, l’HPA
bige-ops add layout custom --runtime nodejs --web same --worker \
  --db postgres --db redis --topology multi-vm --lbu
bige-ops estimate --json

Le layout nommé node-app pose directement une stack Node prod-like (MongoDB, Redis, Weaviate, LBU) ; node-lite reste le démarrage le plus rapide. Détail : layouts & topologies.

Ce que le scan bige-ops fait pour Node.js

Le mode direct tourne sans clé ni LLM, sur ton poste : bige-ops lit le code JavaScript et TypeScript de ton dépôt et croise trois analyses.

  • Routes exposées : un module par framework (Express, Fastify, Hono, Koa, LoopBack, NestJS, Next.js, tRPC). Pour chaque route, bige-ops cherche un signal d’authentification proche (passport, JWT, session, guards, preHandler, protectedProcedure…) ; une route marquée publique, ou une route sensible (/admin, /account, /payment, /billing…) sans signal d’authentification à proximité, ressort « non sécurisée » (CWE-639), en priorité haute pour l’admin et le paiement.
  • Failles de code : secrets en dur (CWE-798), eval et child_process (CWE-78), SQL construit par concaténation ou template string (CWE-89), CORS * (CWE-942), NODE_TLS_REJECT_UNAUTHORIZED=0 (CWE-295), XSS DOM (CWE-79), redirection ouverte (CWE-601), traversée de chemin (CWE-22).
  • Dépendances npm : dependencies, optionalDependencies et peerDependencies de chaque package.json sont rapprochées d’OSV, avec l’identifiant CVE quand il existe.

Avec ta clé OpenCVE, l’image node de tes Dockerfile est rapprochée de Node.js sur OpenCVE ; une image en latest est signalée. Les tests, specs et suites e2e sont écartés pour éviter les faux positifs.

Règle d’or, quelle que soit la base : jamais exposée à Internet. En multi-VM elle vit dans le subnet privé, sans IP publique, derrière un security group limité au CIDR du Net ; sur OKS elle reste un Service interne (ClusterIP). Détail : réseau · ouvrir ou non et bases de données.

Versions à épingler

En production, Node.js recommande une version LTS : aujourd’hui Node.js 24 (LTS active) ou 22 (LTS de maintenance) ; Node.js 26 est en phase Current et Node.js 20 n’est plus maintenu. Épingle la majeure dans ton Dockerfile (FROM node:24-alpine) plutôt que node:latest. Calendrier : versions de Node.js · CVE du runtime : Node.js sur OpenCVE.

OpenCVE, le référentiel CVE de bige-ops

Pour savoir quelles vulnérabilités touchent les briques de ta stack, bige-ops s’appuie sur OpenCVE. OpenCVE agrège les CVE publiées (NVD, MITRE, catalogue KEV de la CISA…), les enrichit avec les scores CVSS et EPSS et les range par fournisseur et par produit, consultables dans son explorateur. Le projet est open source : son code, ses issues et les contributions de sa communauté vivent sur GitHub, et il s’installe aussi chez toi. Merci à ses mainteneurs et à tous ceux qui font vivre ce référentiel : c’est grâce à eux que chaque composant de ta simulation a sa fiche CVE à jour.
