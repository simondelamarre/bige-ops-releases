bige-ops Gratuit

VMs Outscale

Compose une topologie compute (type Tina, disques, réseau), estime-la, génère le Terraform, puis apply sur ton compte. Une fois la stack en place, l’exploitation au quotidien (patchs OS, montée en charge) se pilote de ton côté.

VM, pas VPS. Outscale parle de VM (l’API historique FCU dit « instance »). Le mot VPS désigne en général un serveur pris dans une grille de tailles fixes ; une VM Outscale, elle, se compose sur mesure.

Lire un type Tina

Un type s’écrit tinavW.cXrYpZ. Exemple : tinav6.c4r8p2 = génération de CPU v6, 4 vCPU, 8 GiB de RAM, niveau de performance 2.

SegmentValeurs publiquesÀ savoir
vW générationv2 à v7v5 = Intel Skylake, v6 = Ice Lake, v7 = Sapphire Rapids ; préfère v5 à v7, les générations v2 à v4 sont en fin de support
cX vCPU1 à 78
rY RAM1 à 1039 GiB
pZ performance1, 2 ou 3p1 = la plus haute et la plus stable (requise pour un flexible GPU), p2 = haute, valeur par défaut, p3 = moyenne

Le chiffre de performance se lit à l’envers : plus il est petit, plus la performance du vCPU est stable dans le temps. Et la génération compte autant que le nombre de vCPU, puisque le tarif du vCPU dépend du couple génération × performance. Référence : Types de VM.

Mono-VM ou multi-VM

En mono-VM (code single-vm), les apps et souvent la data partagent une VM (*-all) : simple pour démarrer, un seul blast radius. En multi-VM (multi-vm), tu sépares les rôles (app, data…) sur plusieurs VMs dans le même Net, toujours via le layout, toujours avec l’estimation du sizing choisi.

Ce que le formulaire pilote

Type Tina (génération, vCPU, RAM, performance), taille et type du disque racine, volumes attachés, subnet public ou privé, IP publique et LBU selon le canvas. Chaque changement réécrit la simulation ; generate produit le Terraform. Tu relis, tu apply, puis tu deploy les apps. Pour ouvrir ou non une face (publique ou data privée) : réseau · ouvrir ou non.

Le périmètre du kit

bige-ops pose une base saine : image officielle, keypair, réseau, disques, apps déployées. Le durcissement, la supervision avancée et l’autoscaling des VMs font partie de ton exploitation — voir périmètre. Les images : OMI. Les disques : volumes BSU.

Kubernetes managé : OKS & pods. Exposition réseau : ouvrir ou non. Data et sauvegardes : bases, OOS. Repos app et Dockerfile : repos · VMs · Docker. Vocabulaire : glossaire. Doc Outscale : À propos des VM.
