VMs Outscale (VPS)

Composer une topologie compute (type Tina, disques, réseau), estimer, générer Terraform, apply sur votre compte. Le patch OS et le scale horizontal fins restent de votre côté.

VM = terme produit. VPS = libellé catalogue Outscale. Chez Outscale on parle souvent de VPS (Virtual Private Server). Dans bige-ops on dit VM — même famille IaaS (instance Tina). Pas un second produit.

Mono-VM vs multi-VM

En mono-VM (topology code single-vm), apps et souvent la data partagent une VM (*-all) : simple pour démarrer, un seul blast radius. En multi-VM (multi-vm), vous séparez les rôles (app, worker, data…) sur plusieurs VMs dans le même Net — toujours via le layout, toujours avec estimate sur le sizing choisi.

Ce que le formulaire pilote

Type d’instance Tina, volumes attachés, placement réseau, liens EIP / LBU selon le canvas. Chaque changement réécrit la simulation ; generate materialize le Terraform. Vous relisez, vous apply, puis deploy les apps. Pour ouvrir ou non une face (publique vs data privée) : réseau · ouvrir ou non (règles projet + Security Groups Outscale).

Kickoff ≠ babysitting

Images OMI, SSH, hardening, monitoring avancé, scaling agressif : hors starter kit. Quand la charge monte, c’est à vous de gérer — voir périmètre.

Alternative Kubernetes managé : OKS & pods. Exposition réseau : ouvrir ou non. Data et backups objet : bases, OOS. Repos app + Dockerfile : repos · VMs · Docker. Vocabulaire : glossaire.
